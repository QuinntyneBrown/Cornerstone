@cornerstone/ui  ·  Angular 21

Set every screen from one stone.

Cornerstone is FaithTech's Angular component library. The keyboard behavior, ARIA relationships, and responsive rules are already solved, so a volunteer with two spare hours can ship a screen that works for everyone who opens it.

Derivation

Change the token and everything downstream of it changes too. No rebuild, no find-and-replace.

What it carries

The tedious half of the work, finished and tested.

Every component is built on the Angular CDK, checked against axe-core in three engines, and shipped as a standalone import you can bring in one piece at a time.

Behavior, not just paint

Focus traps, overlay positioning, live regions, and typeahead come from the Angular CDK rather than from a stylesheet that only looks the part.

Tokens all the way down

Every decision is a CSS custom property. Override one on :root or on a single subtree and the change lands everywhere, with no build step.

Standalone and zoneless

Import the three pieces a screen uses instead of a module barrel. Everything runs OnPush and needs no zone.js.

Dark and high contrast, handled

Put .cs-theme-dark on any ancestor. Motion collapses under reduced-motion, and borders resolve to system colors when forced colors are on.

A bridge, not a rewrite

One optional stylesheet keeps Word Up's wu-* vocabulary and Liturgy's primitives rendering while templates move over a screen at a time.

Budgeted in public

The build fails if the published bundle passes 400 KiB gzip or the theme passes 30 KiB. Weight is a contract, not an afterthought.

Setting out

Three steps to the first screen.

Install, name the theme, import what you use. There is no module to register and no provider to remember.

  1. 01

    Install the package

    The CDK is a peer dependency, so your application controls its version. 

    $ npm install @cornerstone/ui @angular/cdk

  2. 02

    Name the theme

    One entry in angular.json loads every token. Add compat.scss after it only if you are migrating. 

    "styles": [
  "@cornerstone/ui/styles/theme.scss",
  "src/styles.scss"
]

  3. 03

    Import only what the screen uses

    Standalone imports mean an unused component never reaches the browser. 

    import { CsButtonDirective, CsCardComponent } from '@cornerstone/ui';

@Component({
  imports: [CsButtonDirective, CsCardComponent],
  templateUrl: './welcome.component.html',
})
export class WelcomeComponent {}

Questions

Before you adopt it.

Will it work in the app I already have?

If that app is on Angular 21 and Node 22, yes. Cornerstone declares the CDK as a peer dependency and ships nothing global beyond the theme stylesheet you name yourself, so it can sit beside whatever you are using today.

What does the compatibility bridge actually change?

Presentation, and only presentation. It reproduces the audited Liturgy and Word Up class vocabularies so old templates keep rendering correctly. It gives you none of the keyboard behavior or ARIA relationships — those come from moving the template to the Angular API. It also adds no CSS at all to applications that never name its export.

How much can I change without forking it?

Color, type, spacing, radius, shadow, motion, and container widths are all CSS custom properties. Set them on :root for the whole application or on any ancestor element to re-theme one subtree. Nothing needs recompiling.

What happens when something has to break?

It is announced two minor releases before it is removed, and an ng update migration rewrites what can be rewritten automatically. Anything left over is reported with the affected file and its manual replacement.

How is accessibility actually verified?

Every build runs axe-core against rendered components in Chromium, Firefox, and WebKit, alongside unit tests for focus order, ARIA relationships, and keyboard interaction. Reduced-motion and forced-colors behavior are part of the theme rather than an opt-in.

Do I need zone.js?

No. Every component runs with OnPush change detection and the reference applications bootstrap zoneless. If your application still uses zone.js, that works too.
